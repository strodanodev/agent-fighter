# Production-readiness audit — 2026-07-18

Code-level audit: every claim below was verified by reading source (file:line
cited), running the verify gate, querying production endpoints, or querying
the live Supabase project. Nothing is assumed from docs or memory. Companion
deliverable: [build-spec-v2.md](build-spec-v2.md) — the spec updated to
as-built reality. Supersedes the scope of `audit-2026-07-17.md` (same-day
drift note: 14 commits landed between the two audits, including protocol
v4→v6, TRAIN MY AGENT / ADR 0006, friendly rooms, dares, arcade, voice/SFX).

## Verdict

**The build is production-deployed but not yet production-ready.** Prod is
live and version-consistent (Railway `af-core-2` / protocol 6 = local HEAD;
Vercel 200; Supabase `persistence:true`, 9 migrations applied). The verify
gate is green (typecheck ×4 packages, 67 core tests, 45 server tests). The
deterministic core is genuinely strong — audited line-by-line with **no
float leaks, no crash paths, and no determinism-breaking bugs found**.

What stands between "deployed" and "ready": **one critical economy exploit
(self-match credit mint — live, unexploited: verified 0 self-matches in 44,
and the ledger reconciles to the credit with balances, 370 = 370)**, one
high-severity verification DoS, an unvalidated feel gate, missing
cross-environment enforcement of the property the money path depends on,
boundary-hardening gaps (client crash-resilience, bundle value validation,
JWT audience, raw-table RLS exposure), and open economy valves.

## First principles — are we following them?

**Largely yes, and measurably.** The five principles the codebase actually
runs on, with audit evidence for and against:

| Principle | Evidence FOR | Evidence AGAINST |
|---|---|---|
| The sim is the only truth | All arithmetic integer fixed-point (verified every `/`, `%`, `*` path); `guards.test.ts` bans hazards at source level; golden hashes never re-blessed since creation — sim behavior stable through 40+ commits of feature work | Browser-vs-Node equivalence is empirical, not CI-gated (spec §2.1 demanded it); in-state `rngSeed` is vestigial dead state — hashed but never read |
| Characters are data | 12 characters, zero character code; schema vocabulary grew (flags, sys.* moves) without a scripting runtime | `loadCharacter` validates shape but not values — negative `meterCost`/`juggleCost`/`chip` produce infinite meter / infinite combos / healing (sim.ts:145,582,555) |
| Everything is an InputSource | autospecial macros, coached agents, AUTO mode, netplay, replays all entered through inputs with zero sim hooks — 4 major features with no core change | AI state lives outside GameState (correct for solo verification, but undocumented as "never a rollback peer") |
| The ledger is the truth for money | Settlement ladder (ADR 0005) settles by re-sim regardless of sockets; idempotent by match id; escrow sweeper settles-then-refunds | Money logic duplicated in SQL + TS mirror; the `NULL = s` incident proved the mirror can't catch SQL semantics; no enforced real-Postgres smoke gate |
| Verification over runners | Trained agents + house AI fight via pinned-config re-derivation — zero marginal cost, cheat-proof, offline presence without processes | Anti-TAS pace check is wall-clock heuristic; bypass valve env-gated (correctly requires AF_ALLOW_DEV_ECONOMY) |

**The clearest first-principles win:** ADR 0006 shipped a whole
agent-coaching product as "a config blob + a token + three HTTP endpoints"
because the architecture already carried it. Features costing near-zero
marginal machinery is what following first principles buys.

**The clearest first-principles drift:** validation at the data boundary.
"Characters are data" only works if the data is bounded; today the engine
trusts bundle values it should reject.

## Code-level findings

### @af/core — determinism STRONG, no bugs found; validation holes real

Full-source audit (fp.ts, sim.ts, state.ts, data.ts, ai.ts, motion.ts, all
tests). Positive confirmations: every division truncated before use; negative
modulo avoided everywhere (`+HIST_LEN*2` before `%`, unsigned `>>>0` in AI);
no product can exceed 2^53; `serialize()` uses fixed field-order arrays;
`serialize.test.ts` proves field completeness at runtime.

Findings (severity · location · scenario):

1. **VALIDATION HOLES (medium now, high at wagering)** — `loadCharacter`
   accepts: negative `meterCost` (super *gains* meter every use, sim.ts:145);
   negative `juggleCost` (juggle budget *increases* per hit — infinite combo,
   sim.ts:582); negative `chip` (heals, and health has no upper clamp,
   sim.ts:555); `maxHealth <= 0`; NaN numerics. Not a desync (both sides sim
   the same data) and no crash path — but a cheating bundle, and the
   validator is what should reject it. **No negative-data tests exist.**
2. **Vestigial `rngSeed`** (state.ts:92) — hashed, never read. Combat has
   zero randomness; only ai.ts consumes randomness on its own stream.
   Harmless; misleading. Document or remove.
3. **AI state is not rollback-safe by design** (ai.ts:67 — not in GameState,
   not snapshotted). Safe only because AI is never a rollback peer; nothing
   asserts that. Add the assertion or the comment.
4. **`aiGrounded` hardcodes floor 460** (ai.ts:153) instead of
   `STAGE.floorYPx` — silently breaks all AI grounded checks if the floor is
   retuned.
5. **Untested edge cases that settle money:** double-KO → both round
   counters advance → `winner=2` draw path (sim.ts:886-888, 952-953, 788);
   exact-health timeout draw; chip KO; KO'd attacker still landing its
   same-tick planned hit (intentional trade design — confirm for wagers);
   corner pushblock transfer; projectile-vs-projectile. Logic reads correct;
   coverage is zero.
6. Spec deltas confirmed in code: charge moves absent; jumps are 3-way up
   (not 8-way); air dash horizontal-only. Accepted in spec v2.

### @af/client + @af/studio — rollback verified sound; crash-resilience gaps

Full read of net.ts, atlas.ts, auth.ts, autospecial.ts, touch.ts, studio
server.mjs + pipeline.ts, build tools; structural read of main.ts/ui.ts.
Positive confirmations: the historical snapshot-ring hash bug is correctly
fixed (bounds traced, net.ts:386-395); reconnect ladder has no soft-lock
path; resume rebuild + `net.game` re-adoption correct (main.ts:1550); **no
sim logic in the client**; autospecial synthesizes only InputFrames; the
vendor-drop deploy bug is structurally fixed (`cpSync` wholesale,
vercel-build.mjs:39); Studio cannot reach production (no deploy config
starts it; path-traversal guards present); AIR token held in JS memory, not
localStorage.

Findings:

1. **HIGH — module-init `localStorage` white-screens the app**
   (main.ts:134): property access at module-eval time, outside any
   try/catch. Sandboxed iframe / hardened-privacy contexts throw
   `SecurityError` → the entire bundle dies before any error UI exists.
   The app is distributed via share/dare links, exactly the context where
   embedding happens. Other modules guard storage; main.ts is the outlier
   (also :410, :575, :657, :788).
2. **MEDIUM — one bad `character.json` aborts the whole roster**
   (main.ts:535 + atlas.ts:110 throw): art 404s degrade gracefully to
   rects, but a single manifest 404 error-screens the entire game. Skip
   and continue instead.
3. **MEDIUM — throttled-but-connected opponent = silent freeze**
   (net.ts:398-401): the stall guard halts the sim, but the "opponent
   disconnected" overlay only triggers on socket drop (`oppgone`). A
   backgrounded mobile peer freezes the match with no on-screen
   explanation until idle-forfeit. Add a visible stall overlay.
4. **LOW — SoloSession mirrors NetSession imperfectly** (net.ts:517,529,
   567): raw-cast account message; xp not folded back into account; resume
   without `solo` throws; AUTO mode not restored after resume.
5. **LOW — dead client progression** (progress.ts `awardXp`/`saveProfile`
   never called): offline-play XP silently frozen since server-authoritative
   XP landed. Remove or reconnect.
6. **Hygiene:** no CSP meta in the single-file bundle (any injected script
   reaches `afAuth().token`); Studio binds all interfaces (`listen(PORT)`,
   server.mjs:449) — bind 127.0.0.1; debug overlay lacks spec §6's
   frame-advantage meter + input history; CLIP QC (spec §5.1 "optional")
   confirmed absent — heuristic QC suite confirmed present.

### @af/server + economy SQL — two launch blockers found

Full read: server.ts (1,357 lines), persist.ts, airjwt.ts, air-issuer.ts,
protocol.ts, migrations 0001–0011. Positive confirmations: refund-then-payout
double-spend structurally impossible (sweeper settles-then-refunds, insert
claimed on-conflict); `coalesce(_deviator = s, false)` correctly applied in
both record_match definitions (the NULL lesson stuck); JSON parsing guarded
and all field access coerced (no crash on garbage); input side is
server-assigned (wrong-side injection impossible); pace-check bypass doubly
env-gated so it cannot ride a live economy; matchEpoch prevents
cross-restart match-id collisions; economy constants mirrored consistently
across SQL and TS.

Findings:

1. **CRITICAL — self-match mints credits** (server.ts:610-644 +
   0002_credits.sql:28). `tryPair` never checks `c0.identity.sub !==
   c1.identity.sub` — I verified this against source directly. Two sockets,
   one AIR token, queue wager on both at a quiet moment → paired against
   yourself. `escrow_match`'s idempotency guard `unique (profile_id,
   reason, match_id)` then swallows the SECOND fee row for the same
   profile+match as a duplicate: only 10 credits collected. Settlement pays
   the winner `fee*2 = 20`. You control both sides, so you always win:
   **net +10 credits per self-match, unbounded**, plus farmed W-L/XP and
   referral-payout triggers. The dev mirror charges the self-pair twice (a
   wash), so tests can never see the production bug — a live demonstration
   of the "money logic lives twice" risk. **Launch blocker.**
2. **HIGH — verification re-sim is a synchronous DoS** (server.ts:986-997,
   358-377). Input ticks capped at 108,000; desync forensics call
   `replayHashAt` once per reported hash (cap 400), each re-simming FROM
   TICK ZERO: up to ~43M sim steps in one synchronous `finishMatch`,
   freezing the event loop — all matches, all sockets, all HTTP — for
   seconds, repeatable. The spec's "verifies in well under a second"
   assumption holds only for honest clients. **Launch blocker.**
3. **HIGH — AIR JWTs accepted without aud/iss/partnerId check**
   (airjwt.ts:59-93). Signature+exp+nbf only; `partnerId` extracted but
   never asserted. Any token signed by AIR's shared JWKS — including one
   minted for a DIFFERENT partner app — is a valid Agent Fighter identity.
   Also: tokens without `exp` never expire.
4. **MEDIUM — `profiles`/`credit_ledger`/`matches` world-readable at the
   raw-table level** (0001:66-68, 0002:34): RLS `using (true)` + default
   anon SELECT grant exposes every column via PostgREST — including
   `agent_key_hash`, wallet `address`, `credits`, and each account's full
   financial history — despite 0007's own comment that agent_key_hash
   "must NEVER ride a public view". Views curate columns; RLS does not.
   Privacy/correlation leak, not takeover (hash is sha256).
5. **MEDIUM — ws hardening absent:** no `maxPayload` (ws default 100 MiB —
   a single frame is buffered and JSON.parsed); no per-connection message
   rate limit; no ping/pong heartbeat (lobby-idle dead sockets never
   reaped); unbounded `clients` set.
6. **LOW:** unknown-`kid` tokens each force an uncached JWKS refetch
   (amplification, no fetch timeout); reputation credentials addressable to
   any client-supplied email; transient escrow errors mislabeled as
   "insufficient credits" and evict the wrong user; `escrow_match` locks
   p0→p1 unsorted (theoretical deadlock); arcade double-play guard relies
   on JS run-to-completion (fragile to any future `await`); solo opponent
   picks from all characters instead of `enabledCharacterIds`; air-issuer
   `perProfile` map never evicts.
7. **Production gaps:** no graceful shutdown (every deploy strands
   liveMatches; resume tokens + arcade runs lost; fees recover only via
   the 30-min sweeper — winners of in-flight matches forfeit winnings);
   health check never probes Supabase/AIR (DB-down invisible); console.log
   only, no structured logs/metrics/alerts; sync `writeFileSync` forensics
   in the settle path.
8. **Spec delta worth adopting:** on persistent desync the spec said VOID
   the match; the code awards the pot to the non-deviating side. Stronger
   for wagering — spec v2 §7 adopts the as-built behavior.

### Supabase (live project, via MCP)

  `rls_auto_enable()` exists remotely with **no repo source** — schema
  drift between git and the live DB. Make the repo the source of truth;
  capture the remote-only function into a migration file.
- Advisors: 3 SECURITY DEFINER functions anon-executable. `win_streak` +
  `house_agent_stats` are read-only over public data (acceptable;
  documented intent). `rls_auto_enable` should have anon EXECUTE revoked.
- `referrals` table: RLS enabled, zero policies (= default-deny to anon;
  fine if only the service role touches it — confirm intent, add a comment
  policy either way).
- Service-role key now lives in TWO deployments (Railway + landing
  Vercel). The landing reads it only server-side (verified: no
  `NEXT_PUBLIC_` prefix on the service key, so Next.js never bundles it) —
  but blast radius doubled; scope a second, weaker key for the landing if
  Supabase's new API-key system allows.

## Red flags (carried + new, priority order)

0. **NEW, CRITICAL — the self-match credit mint (server finding 1).** Live
   in production right now. Requires only two browser tabs and patience.
   Every other economy discussion is moot while an unbounded mint exists.
   The one-line guard (refuse to pair identical subs; also void `_p0 = _p1`
   in escrow_match) should ship before anything else in this report.
1. **CARRIED, still open — the feel gate.** Zero external playtests as of
   this audit. Now compounded by: dare links, arcade, and Minds onboarding
   are all acquisition surfaces pointed at a game whose core promise
   ("feels like MvC") is unvalidated by anyone but its builders.
2. **CARRIED, still open — no browser-vs-Node determinism gate in CI.**
   The single highest-consequence missing test. Every settled credit
   assumes it.
3. **NEW — bundle value-validation holes** (infinite meter/combo/heal).
   Low today (first-party bundles only), critical the day any third-party
   or user-influenced bundle path opens.
4. **NEW — client crash-resilience** (white-screen on storage denial;
   roster-wide abort on one manifest; silent netplay freeze). These are
   launch-audience-facing: share links and embeds are exactly where the
   storage-denial contexts live.
5. **CARRIED — economy valves open** (human daily-grant sybil, solo-farm
   caps). Non-convertibility remains the only guard and is now formally
   written as a release gate in spec v2 §9.
6. **NEW — schema drift** between repo migrations and the live database.
   Small today; compounds with every MCP-applied hotfix.
7. **Velocity itself.** 14 commits and two protocol bumps landed *during
   this audit*. The guardrails held (goldens never wrongly re-blessed,
   verify green throughout) — but audit-to-reality latency is hours, and
   any production-readiness declaration is a snapshot. Freeze-and-gate
   before launch moments.

## Recommendations — next steps

**P-1 — HOTFIX the credit mint (hours, today).** (a) `tryPair`: skip
pairing when both queued clients share a sub (re-queue one); (b)
`escrow_match`: `if _p0 = _p1 then raise` as defense in depth; (c) a
regression test that self-queues one identity twice and asserts no pairing
and no net credit change — against real Postgres, since the dev mirror
provably diverges here. Then reconcile: query `credit_ledger` for
self-matches (`matches where p0 = p1`) to measure whether it was ever
exploited.

**P0 — Run the feel gate (unchanged, now urgent).** Every new acquisition
surface (dares, arcade, Minds) multiplies the cost of a "feels floaty"
verdict arriving late. 2–3 external MvC players, live build, one question.

**P1 — CI: browser-vs-Node golden replay.** Headless browser runs the
existing golden scenarios; assert hash equality with Node. Closes the
money path's undefended assumption. ~Half-day of work with Playwright.

**P2 — Boundary hardening sprint (one day):**
  a. `loadCharacter` value bounds + negative-data tests (core).
  b. Guard main.ts module-init storage access; skip-not-abort roster load;
     visible netplay stall overlay (client).
  c. CSP meta tag in bundle.mjs; Studio bind 127.0.0.1.
  d. Server: ws `maxPayload` (few KB) + per-connection message rate limit
     + ping/pong heartbeat; bound verification work (cap re-sim ticks to
     match wall-clock plausibility BEFORE simming; memoize `replayHashAt`
     forensics with one forward pass instead of from-zero per hash — or
     move verification to a worker thread); assert `iss`/`partnerId` and
     require `exp` in airjwt; negative-cache unknown JWKS kids + fetch
     timeout.
  e. Supabase: replace raw-table `using (true)` SELECT policies on
     `profiles`/`credit_ledger` with column-curated views only (revoke
     anon table SELECT); the `ask_leads` no-select-policy pattern is the
     model.

**P3 — Money-path drills:** negative tests for double-KO/draw settlement;
real-Postgres smoke script as a repo command (`npm run smoke:sql`); write
the "no cash-out until valves closed + signatures + legal review" gate into
AGENTS.md so no future session ships past it.

**P4 — Reconcile Supabase state:** export remote-only objects into repo
migrations; revoke anon EXECUTE on `rls_auto_enable`; decide `referrals`
policy posture; consider a scoped key for the landing.

**P5 — Observability before launch:** structured match-id logs, a
verify-failure alert (a spike = determinism drift or an attack — either
demands eyes), uptime check on `/`, and a daily economy reconciliation
query (sum of ledger deltas vs profile balances).

**Then:** the client refactor (ui.ts/main.ts), remaining VS poses, dead
progress.ts code — quality-of-life, not gates.
